Vue + Spring Boot — Componentes Básicos
A combinação de Vue com Spring Boot é, essencialmente, a integração de um framework frontend reativo com um framework backend Java robusto. Diferente do Supabase (que é uma plataforma pronta), o Spring Boot exige que você construa a API, os modelos de dados e as regras de segurança do zero, mas em troca oferece controle total sobre o backend.

🏗️ Arquitetura da Stack
A arquitetura típica é frontend-backend separado: o Vue roda como SPA (Single Page Application) e se comunica com o Spring Boot via REST API.

text
Vue 3 (Vite)  ──HTTP/Axios──►  Spring Boot  ──JPA──►  Banco de Dados
   :5173                          :8080                   (MySQL/PostgreSQL)
O backend é um servidor Tomcat embutido que expõe endpoints RESTful, enquanto o frontend é servido separadamente durante o desenvolvimento e geralmente empacotado como arquivos estáticos na produção.

🚀 Estrutura do Projeto Spring Boot
Configuração Inicial
Projetos Spring Boot modernos usam o Spring Initializr para gerar a estrutura base. As dependências essenciais para uma API REST com persistência são:

Dependência	Função
spring-boot-starter-web	Cria a API REST e embute o Tomcat
spring-boot-starter-data-jpa	Abstrai o acesso ao banco de dados
spring-boot-starter-security	Autenticação e autorização
Driver do banco (MySQL/PostgreSQL)	Conexão com o SGBD
A Classe Principal
O ponto de entrada é uma classe anotada com @SpringBootApplication, que combina três anotações: @Configuration, @EnableAutoConfiguration e @ComponentScan. O método main delega para SpringApplication.run(), que inicializa o contexto Spring e o servidor embutido.

java
@SpringBootApplication
public class Application {
    public static void main(String[] args) {
        SpringApplication.run(Application.class, args);
    }
}
🗄️ CRUD com Spring Data JPA
O coração da persistência é o Repository, uma interface que estende JpaRepository e fornece métodos CRUD prontos sem escrever SQL.

Entidade (Model)
java
@Entity
public class Bookmark {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;
    
    @NotEmpty(message = "Title is required")
    private String title;
    
    @NotEmpty(message = "Url is required")
    private String url;
    
    private Instant createdAt;
    
    // getters e setters
}
Repository
java
public interface BookmarkRepository extends JpaRepository<Bookmark, Long> {
}
Só com isso o Spring cria automaticamente save, findAll, findById, deleteById e outros.

Controller REST
O Controller expõe os endpoints HTTP. Cada método é mapeado para uma operação CRUD:

java
@RestController
@RequestMapping("/api/bookmarks")
public class BookmarkController {
    
    private final BookmarkRepository repository;
    
    // CREATE
    @PostMapping
    ResponseEntity<Void> create(@Valid @RequestBody Bookmark payload) {
        var saved = repository.save(payload);
        var location = ServletUriComponentsBuilder.fromCurrentRequest()
            .path("/{id}")
            .build(saved.getId());
        return ResponseEntity.created(location).build();
    }
    
    // READ (todos)
    @GetMapping
    List<Bookmark> listar() {
        return repository.findAll();
    }
    
    // UPDATE
    @PutMapping("/{id}")
    ResponseEntity<Void> update(@PathVariable Long id, 
                                @Valid @RequestBody Bookmark payload) {
        var bookmark = repository.findById(id)
            .orElseThrow(() -> new BookmarkNotFoundException("Bookmark not found"));
        bookmark.setTitle(payload.getTitle());
        bookmark.setUrl(payload.getUrl());
        repository.save(bookmark);
        return ResponseEntity.noContent().build();
    }
    
    // DELETE
    @DeleteMapping("/{id}")
    void delete(@PathVariable Long id) {
        repository.deleteById(id);
    }
}
Tratamento de Exceções
Spring Boot retorna 500 por padrão quando uma exceção é lançada. Para retornar o status correto (ex.: 404 para recurso não encontrado), usa-se um @ExceptionHandler:

java
@ExceptionHandler(BookmarkNotFoundException.class)
ResponseEntity<Void> handle(BookmarkNotFoundException e) {
    return ResponseEntity.notFound().build();
}
🔐 Autenticação com JWT
Diferente do Supabase (que tem Auth pronto), no Spring Boot a autenticação é implementada manualmente usando Spring Security + JWT. O fluxo é stateless: o token é enviado em cada requisição e validado a cada chamada.

Dependências
xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-security</artifactId>
</dependency>
<dependency>
    <groupId>io.jsonwebtoken</groupId>
    <artifactId>jjwt-api</artifactId>
    <version>0.12.6</version>
</dependency>
<dependency>
    <groupId>io.jsonwebtoken</groupId>
    <artifactId>jjwt-impl</artifactId>
    <version>0.12.6</version>
</dependency>
JwtTokenProvider
Componente responsável por gerar e validar tokens:

java
@Component
public class JwtTokenProvider {
    
    @Value("${app.jwt.secret}")
    private String jwtSecret;
    
    @Value("${app.jwt.expiration-ms}")
    private long jwtExpirationMs;
    
    public String generateToken(UserDetails userDetails) {
        Date now = new Date();
        Date expiry = new Date(now.getTime() + jwtExpirationMs);
        SecretKey key = Keys.hmacShaKeyFor(Decoders.BASE64.decode(jwtSecret));
        
        return Jwts.builder()
            .subject(userDetails.getUsername())
            .claim("roles", userDetails.getAuthorities())
            .issuedAt(now)
            .expiration(expiry)
            .signWith(key)
            .compact();
    }
    
    public boolean validateToken(String token) {
        try {
            Jwts.parser().verifyWith(key).build().parseSignedClaims(token);
            return true;
        } catch (JwtException | IllegalArgumentException e) {
            return false;
        }
    }
}
Fluxo de Login
Etapa	Frontend	Backend
1. Login	POST /api/auth/login com credenciais	Valida usuário e senha
2. Token	Armazena JWT em localStorage	Gera token com roles
3. Requests	Axios envia Authorization: Bearer <token>	JwtAuthenticationFilter valida e define contexto
4. Expiração	401 → redireciona para login	Token inválido → 401
Filtro de Autenticação
O JwtAuthenticationFilter intercepta cada requisição, extrai o token do header, valida e define a autenticação no SecurityContextHolder.

java
@Component
public class JwtAuthenticationFilter extends OncePerRequestFilter {
    
    @Override
    protected void doFilterInternal(HttpServletRequest request,
                                    HttpServletResponse response,
                                    FilterChain filterChain) {
        String token = extractToken(request);
        if (token != null && tokenProvider.validateToken(token)) {
            String username = tokenProvider.getUsernameFromToken(token);
            UserDetails user = userDetailsService.loadUserByUsername(username);
            var auth = new UsernamePasswordAuthenticationToken(
                user, null, user.getAuthorities());
            SecurityContextHolder.getContext().setAuthentication(auth);
        }
        filterChain.doFilter(request, response);
    }
}
📡 Integração Frontend: Axios + Vue
Configuração do Axios
A integração eficiente requer interceptors para injetar o token automaticamente e tratar respostas padronizadas:

ts
import axios from 'axios'
import { ElMessage } from 'element-plus'
import router from '@/router'

const service = axios.create({
  baseURL: '/api',
  timeout: 5000
})

// Injeta token em toda requisição
service.interceptors.request.use(config => {
  const token = localStorage.getItem('token')
  if (token) config.headers.Authorization = `Bearer ${token}`
  return config
})

// Trata resposta padronizada
service.interceptors.response.use(
  res => {
    if (res.data.code !== 200) {
      ElMessage.error(res.data.msg || '请求失败')
      return Promise.reject(res.data)
    }
    return res.data
  },
  err => {
    if (err.response?.status === 401) {
      ElMessage.warning('登录已过期')
      localStorage.removeItem('token')
      router.push('/login')
    }
    return Promise.reject(err)
  }
)

export default service
Estrutura de Resposta Padronizada
O backend Java geralmente encapsula respostas em um formato uniforme:

json
{
  "code": 200,
  "msg": "成功",
  "data": { ... }
}
Isso permite que o frontend trate todos os erros de negócio de forma centralizada no interceptor de resposta.

⚠️ Problema Crítico: CORS (Cross-Origin Resource Sharing)
Como Vue (:5173) e Spring Boot (:8080) rodam em portas diferentes, o navegador bloqueia requisições por política de mesma origem. A solução recomendada é configurar CORS no backend.

Configuração Global (Recomendada)
java
@Configuration
public class CorsConfig implements WebMvcConfigurer {
    @Override
    public void addCorsMappings(CorsRegistry registry) {
        registry.addMapping("/**")
                .allowedOrigins("http://localhost:5173")
                .allowedMethods("GET", "POST", "PUT", "DELETE")
                .allowedHeaders("*")
                .allowCredentials(true);
    }
}
Alternativa: Proxy no Vite (Apenas Desenvolvimento)
js
// vite.config.js
export default defineConfig({
  server: {
    proxy: {
      '/api': {
        target: 'http://localhost:8080',
        changeOrigin: true
      }
    }
  }
})
A configuração no backend é preferível porque funciona em todos os ambientes (dev, produção), enquanto o proxy do Vite só resolve em desenvolvimento.

⚡ Spring Boot vs Supabase/Firebase: Diferenças-Chave
Dimensão	Spring Boot	Supabase	Firebase
Controle	Total — você escreve tudo	Alto — open source, self-hosted	Baixo — fechado
Linguagem	Java/Kotlin	SQL/JS	JS/NoSQL
Autenticação	Manual (Spring Security + JWT)	Pronto (Auth)	Pronto (Auth)
Banco	Qualquer (JPA)	PostgreSQL	Firestore
Real-time	WebSocket manual	Realtime nativo	Snapshot nativo
Deploy	Você gerencia (Docker/Cloud)	Gerenciado ou self-hosted	Gerenciado
Curva de aprendizado	Alta	Média	Baixa
Ideal para	Times Java, apps enterprise	Apps SQL com agilidade	Apps rápidos, mobile-first
Escolha: Se seu time já domina Java e você precisa de controle total sobre a lógica de negócio, Spring Boot é a escolha. Se você quer velocidade de desenvolvimento e não quer gerenciar backend, Supabase ou Firebase são mais adequados.

✅ Checklist de Boas Práticas
Prática	Descrição
Configurar CORS no backend	Funciona em todos os ambientes, não só no dev
Usar JWT com expiração curta	Tokens de longa duração são um risco de segurança
Interceptor de resposta no Axios	Centraliza tratamento de erro e logout automático
Validar payloads com @Valid	Jakarta Bean Validation previne dados inválidos
Tratar exceções com @ExceptionHandler	Retorna status HTTP corretos (404, 400, 401)
Nunca versionar secrets	Use variáveis de ambiente ou vault
Testar endpoints com MockMvc	Spring Boot fornece spring-boot-starter-test
Usar DTOs em vez de entidades	Evita expor detalhes do banco na API
