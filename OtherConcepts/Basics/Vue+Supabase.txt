Vue + Supabase — Componentes Básicos
A combinação de Vue com Supabase é, essencialmente, a integração de um framework frontend reativo com uma plataforma backend de código aberto baseada em PostgreSQL. A maior diferença em relação ao Firebase é que o Supabase oferece um banco de dados relacional SQL de verdade, e as políticas de segurança são aplicadas pelo próprio banco através do Row Level Security (RLS).

🚀 Configuração Inicial
O cliente Supabase precisa de uma URL e de uma publishable key (antigamente chamada de anon key), ambas obtidas nas configurações do projeto.

js
// src/supabase.js
import { createClient } from '@supabase/supabase-js'

const supabaseUrl = import.meta.env.VITE_SUPABASE_URL
const supabaseKey = import.meta.env.VITE_SUPABASE_PUBLISHABLE_KEY

export const supabase = createClient(supabaseUrl, supabaseKey)
Variáveis de ambiente (.env.local):

text
VITE_SUPABASE_URL=sua-url-aqui
VITE_SUPABASE_PUBLISHABLE_KEY=sua-chave-aqui
O Supabase oferece blocos oficiais de shadcn-vue para instalar rapidamente a configuração do cliente:

bash
npx shadcn-vue@latest add @supabase/supabase-client-vue
🗄️ CRUD no Banco de Dados (Consultas Postgres)
As operações de dados no Supabase são feitas através de chamadas encadeadas com supabase.from(), que sempre retornam uma estrutura { data, error }.

Consultar (Select)
js
// Consultar um único registro
const { data, error } = await supabase
  .from('profiles')
  .select('username, website, avatar_url')
  .eq('id', userId)
  .single()

// Consultar lista
const { data } = await supabase.from('produtos').select('*')
Inserir (Insert)
js
const { data, error } = await supabase
  .from('produtos')
  .insert([{ nome: 'Teclado', preco: 199.9 }])
Atualizar (Update)
js
const { error } = await supabase
  .from('produtos')
  .update({ preco: 179.9 })
  .eq('id', produtoId)
Deletar (Delete)
js
const { error } = await supabase
  .from('produtos')
  .delete()
  .eq('id', produtoId)
Upsert (Inserir ou Atualizar)
O upsert do Supabase é muito útil, especialmente em cenários de "atualizar perfil" — se o registro existe, ele atualiza; se não, ele cria.

js
const updates = {
  id: userId,
  username: 'novo-nome',
  updated_at: new Date()
}

const { error } = await supabase.from('profiles').upsert(updates)
🔄 Dados em Tempo Real (Realtime)
O Supabase Realtime é baseado no mecanismo de replicação lógica do PostgreSQL. Diferente do Firebase, que "escuta documentos", o Supabase escuta eventos reais de alteração nas tabelas do banco (INSERT / UPDATE / DELETE).

Configurar a replicação da tabela
No Dashboard do Supabase, é preciso habilitar o Realtime para a tabela desejada. Ou executar no SQL Editor:

sql
alter publication supabase_realtime add table sua_tabela;
Assinatura Realtime em um componente Vue
vue
<script setup>
import { ref, onMounted, onUnmounted } from 'vue'
import { supabase } from '@/supabase'

const itens = ref([])
let channel = null

onMounted(() => {
  // Carregamento inicial
  carregarItens()

  // Assinar mudanças em tempo real
  channel = supabase
    .channel('itens-changes')
    .on(
      'postgres_changes',
      { event: '*', schema: 'public', table: 'itens' },
      (payload) => {
        console.log('Mudança:', payload)
        carregarItens() // Recarregar ou atualizar o estado local manualmente
      }
    )
    .subscribe()
})

async function carregarItens() {
  const { data } = await supabase.from('itens').select('*')
  itens.value = data ?? []
}

onUnmounted(() => {
  if (channel) supabase.removeChannel(channel)
})
</script>
Diferença chave em relação ao Firebase: os eventos Realtime do Supabase trazem payload.eventType (INSERT/UPDATE/DELETE) e o snapshot completo das linhas em new/old. Isso permite atualizar o array local com precisão, sem precisar refazer a consulta inteira.

🔐 Authentication (Autenticação)
O Supabase Auth é construído sobre o PostgreSQL. Os usuários ficam armazenados na tabela auth.users, o que torna muito direto vincular dados do usuário às tabelas de negócio.

Login com Magic Link (sem senha)
É o método mais recomendado no tutorial oficial de Vue 3:

vue
<script setup>
import { ref } from 'vue'
import { supabase } from '@/supabase'

const loading = ref(false)
const email = ref('')

const handleLogin = async () => {
  try {
    loading.value = true
    const { error } = await supabase.auth.signInWithOtp({
      email: email.value
    })
    if (error) throw error
    alert('Verifique seu email para o link de login!')
  } catch (error) {
    alert(error.message)
  } finally {
    loading.value = false
  }
}
</script>
Login/Registro com Email + Senha
js
// Registro
const { data, error } = await supabase.auth.signUp({
  email: email.value,
  password: password.value
})

// Login
const { data, error } = await supabase.auth.signInWithPassword({
  email: email.value,
  password: password.value
})

// Logout
await supabase.auth.signOut()
Obter o usuário atual
O Supabase recomenda usar getClaims() para validar a identidade (decodifica o JWT e, se necessário, renova a sessão automaticamente). É mais eficiente do que getUser().

js
const { data: { claims } } = await supabase.auth.getClaims()
if (claims) {
  console.log(claims.sub) // ID do usuário
  console.log(claims.email)
}
Proteção de rotas (Vue Router)
js
// router/index.js
import { supabase } from '@/supabase'

router.beforeEach(async (to) => {
  if (!to.meta.requiresAuth) return true

  const { data: { claims } } = await supabase.auth.getClaims()
  if (!claims) {
    return { path: '/login' }
  }
})
Uma abordagem mais moderna também é verificar o estado de autenticação no onMounted e redirecionar manualmente.

🛡️ Row Level Security (Mecanismo Central de Segurança)
Esta é a diferença mais fundamental em relação ao Firebase: as políticas de segurança ficam escritas dentro do banco, aplicadas pelo PostgreSQL, e não em um arquivo separado de regras ou no frontend.

Habilitar RLS e criar políticas
sql
-- Habilitar RLS
alter table profiles enable row level security;

-- Usuário só pode ver o próprio perfil
create policy "Users can view own profile"
on profiles for select
to authenticated
using ( (select auth.uid()) = user_id );

-- Usuário só pode atualizar o próprio perfil
create policy "Users can update own profile"
on profiles for update
to authenticated
using ( (select auth.uid()) = user_id )
with check ( (select auth.uid()) = user_id );

-- Usuário só pode deletar o próprio perfil
create policy "Users can delete own profile"
on profiles for delete
to authenticated
using ( (select auth.uid()) = user_id );
Pontos-chave:

using define quais linhas são visíveis/operáveis

with check define se a linha modificada é válida (evita que alguém troque o user_id para o de outra pessoa)

Para executar UPDATE, é obrigatório ter também uma política de SELECT, senão a atualização não tem efeito

Envolver a chamada da função com (select auth.uid()) permite que o otimizador do Postgres faça cache do resultado, evitando chamadas linha a linha

Criar índices para as colunas das políticas
As políticas de RLS avaliam o filtro em cada linha, então as colunas usadas nas políticas precisam ter índice:

sql
create index profiles_user_id_idx on profiles using btree (user_id);
📦 Storage (Upload de Arquivos)
O Supabase Storage gerencia arquivos como avatares e imagens, e também é protegido por políticas RLS, igual ao banco.

js
// Upload
const { data, error } = await supabase.storage
  .from('avatars')
  .upload(filePath, file)

// Obter URL pública
const { data } = supabase.storage
  .from('avatars')
  .getPublicUrl(filePath)
⚡ Supabase vs Firebase: Diferenças-Chave na Integração com Vue
Dimensão	Supabase	Firebase
Banco de dados	PostgreSQL (SQL, tipagem forte, chaves estrangeiras)	Firestore (NoSQL, modelo de documentos)
Políticas de segurança	RLS escrita no banco, aplicada pelo Postgres	Regras em arquivo separado, fáceis de configurar errado
Mecanismo realtime	Replicação lógica do Postgres, escuta mudanças reais nas tabelas	Snapshot listeners do Firestore
Integração com Auth	Usuários em auth.users, permitindo JOIN direto com tabelas de negócio	Sistema de usuários independente
Auto-hospedagem	Totalmente open source, pode ser auto-hospedado em Docker/K8s	Fechado, sem auto-hospedagem
Suporte offline	Em melhoria, ainda inferior ao Firebase	Maduro e completo
Desenvolvimento local	supabase start sobe a stack completa (Postgres + Auth + Storage + Edge Functions)	Emulator Suite
Recomendação de escolha: se seus dados têm relacionamentos complexos (usuário-pedido-produto), você precisa de capacidade de consulta SQL ou quer auto-hospedar, o Supabase é a escolha mais adequada. Se offline-first for um requisito central, ou se o time já usa profundamente o Google Cloud, o Firebase ainda tem vantagem.

✅ Checklist de Boas Práticas
Prática	Descrição
Usar getClaims() e não getUser() para proteção de rotas	Decodifica o JWT localmente e renova a sessão se necessário, sem custo de rede
Habilitar RLS em todas as tabelas por padrão	O Supabase avisa ao criar tabelas — não ignore
Envolver chamadas de auth.uid() nas políticas	(select auth.uid()) permite que o Postgres faça cache do resultado
Criar índice para colunas usadas em políticas	Caso contrário, o RLS causa full table scan
Política de UPDATE precisa de política de SELECT	Sem permissão de SELECT, o UPDATE falha silenciosamente
Limpar canais Realtime ao desmontar o componente	supabase.removeChannel(channel) evita memory leak
Usar .single() quando se espera um único registro	Semântica clara e tratamento de erro melhor
Isolar caminhos de upload por ID de usuário	avatars/{userId}/file.png facilita o controle por RLS
